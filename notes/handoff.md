# Codex 작업 인계

갱신: 2026-11-04 (Asia/Seoul). 이 파일은 두 Codex 세션의 작업 연속성을 위한 비민감 요약이다. 인증정보, 회사 자료의 원문·수치·내부 경로·제품 식별자·개인 이름을 포함하지 않는다.

## 현재 목표

현재 작업 폴더의 프로젝트 문서를 조사해 경력 기술 초안을 정리한다. 프로젝트 개요, 기술 문제 해결 사례, 이력서 성과 후보와 측정 조건·근거, 개인 역할 확인 질문 5개 이내를 작성한다. 결과는 `drafts/`에 둔다.

공유 범위: 사용자가 이 인계 파일 하나를 GitHub 연결 도구로 신규 커밋하도록 승인했다. 대상은 지정 저장소의 `notes/handoff.md`이며, 원격 파일이 이미 존재하면 덮어쓰지 않고 알린다. `drafts/`와 다른 파일은 공유 대상에서 제외한다.

## 제약

- 기존 파일·체크아웃·원문 문서를 덮어쓰거나 수정하지 않는다.
- 프로젝트 전체를 사용자의 개인 기여로 간주하지 않는다.
- AI 활용은 문제 정의·실험 설계·구현·검증·최종 판단으로 나눠 귀속을 확인한다.
- 실험 후보, 릴리스 결정, 제품 탑재·출하를 구분한다.
- 데이터·GT·평가기·임계값·후처리·장치 조건이 다른 수치를 직접 비교하지 않는다.
- 최신 판단과 정정을 과거 요약보다 우선한다. 최신 상태의 구체 내용은 비공개 근거 문서에서 확인한다.
- 공개용 초안은 회사·제품명과 내부 경로를 익명화한다. 미확정은 `[확인 필요]`로 표시한다.
- 익명화된 기술 수치도 외부 공개 허용 여부를 확인한다. 이 인계 파일에는 그런 수치를 복사하지 않는다.
- 인증정보 출력·복사·추가 인증 설정을 하지 않는다. 원격 쓰기는 사용자가 승인한 인계 파일의 신규 생성으로 한정한다.

## 확인된 사실과 근거

- 현재 폴더는 `notes/`다. 따라서 요청한 `notes/handoff.md`는 이 파일이다.
- 현재 로컬 작업 폴더는 Git 저장소가 아니다. `.git/` 디렉터리는 비어 있고 `git rev-parse --show-toplevel`도 실패했다.
- 사용자가 지정한 저장소의 `main` 브랜치는 GitHub 연결 도구로 접근했다. 조사 기준 커밋 식별자는 `drafts/`의 내부 조사 보고서에 기록했다.
- 기존 대상 체크아웃은 발견하지 못했다. 샌드박스 안의 Git 접근 확인·clone은 호스트 이름 해석 오류로 실패했다. 이후 승인된 샌드박스 밖 읽기 전용 `git ls-remote`는 성공해 `main` 접근을 확인했다. 오류는 샌드박스 네트워크 제약에 따른 것으로 판단한다. **로컬 clone은 완료되지 않았다.** 연결 도구 열람을 체크아웃으로 오인하지 않는다.
- 로컬 지침 파일과 원격 트리의 작업 지침 이름을 확인했다. 별도 에이전트 지침 파일은 발견되지 않았고, 문서 안내·작업 절차를 먼저 읽었다.
- 사용자가 우선 지정한 현재 안내, 최신 날짜별 기록, 과거 통합 기록을 조사했다. 후속 기록에서 과거 수치의 측정 조건 정정을 발견해 초안에 반영했다.
- 원본 모델·영상·보드 덤프를 실행해 검증한 작업은 아니다. 연결된 외부 판정 화면도 독립 검증하지 않았다.
- 개인 기여·공개 허용·실제 제품 출하는 아직 확정되지 않았다. 근거는 조사 보고서와 질문 파일에 구분했다.

## 완료 작업

- 연결 도구 및 샌드박스 밖 Git 읽기 접근 확인, 로컬 clone 실패 원인과 Git 저장소 부재 기록.
- 문서 지침 확인과 우선 문서 조사, 시점별 정정·완료·보류 구분.
- 내부 조사 보고서, 익명화 검토용 경력 초안, 기여 확인 질문 파일 작성.
- 기존 프로젝트 문서는 수정하지 않았다. 이 인계 파일의 신규 원격 커밋만 승인됐으며, 공유 완료 여부와 커밋 SHA는 실행 결과로 별도 확인한다.

산출물은 `drafts/`에 있다. `internal`이 포함된 보고서는 비공개 검토용이다. `public` 초안도 공개 승인 완료본이 아니다. 다른 세션이나 외부 시스템에 자료를 넘기기 전에 해당 세션의 열람 권한을 확인한다. 이 인계 파일에 비공개 보고서의 내용을 그대로 붙이지 않는다.

## 미확정 질문

질문은 `drafts/`의 기여 확인 파일에 5개로 정리했다. 다음 사항의 답변을 기다린다.

1. 참여 기간·역할과 단계별 본인·동료·AI 담당 범위.
2. 실험·평가 설계 및 채택 판단에서의 본인 기여.
3. AI 생성물과 직접 작성·수정·오류 검증 사례의 구분.
4. 실제 실측·육안 검수 수행자와 책임 범위.
5. 탑재·출하 확인 여부 및 외부 공개 가능한 정보 범위.

## 다음 단계

1. 이 인계 파일 전체에서 인증정보·회사 비공개 자료가 없는지 확인하고, 원격 대상 파일의 부재를 재확인한 뒤 파일 하나만 신규 커밋한다. 이미 존재하면 덮어쓰지 않고 알린다. 완료 후 커밋 SHA와 파일 URL을 사용자에게 전달한다.
2. 사용자의 기여·공개 범위 답변을 받아 초안의 `[확인 필요]`를 근거 있는 문장으로 바꾼다. 답변 전에는 개인 성과로 확정하지 않는다.
3. 권한이 있는 환경에서 로컬 checkout이 필요하면 기존 `codex/` 상태부터 확인한다. 새 파일이 생겼다면 덮어쓰지 않는다. 네트워크 제약을 우회하거나 인증정보를 복사하지 않는다.
4. 추가 조사 시 보고서의 고정 커밋 근거를 사용하고, 다른 시점 자료를 읽었다면 새 커밋·차이를 별도 기록한다.
5. 공개 문안에는 허용된 사실만 남긴다. 조사 기록의 링크·회사 자료·내부 경로를 공개 문안이나 인계 파일에 옮기지 않는다.
6. 승인된 인계 파일 공유 외의 commit·push는 별도 요청 없이 하지 않는다. 두 세션이 동시에 편집한다면 먼저 파일 상태를 읽고 담당 파일을 나눠 충돌을 방지한다.
