## 작성 규칙

- 현재 지원하는 기능·실행 방법은 `docs/`, 과거 계획·검토·실행 기록은 `docs/archive/`에 둔다.
- 파일명은 목적을 나타내는 영문 소문자와 밑줄을 사용한다. `README.md`는 목록·규칙용이다.
- 제목은 파일당 `#` 하나, 본문은 `##`·`###`로 구성한다. 현재 문서에는 수동 절 번호를 붙이지 않는다.
- 제목 아래에 적용 범위와 기준일(`YYYY-MM-DD`)을 적는다. 과거 측정일을 문서 수정일로 바꾸지 않는다.
- 사용법은 **실행 환경 → 명령어 → 옵션 → 결과**, 상세 규격은 **입력 → 처리 규칙 → 출력 → 제약** 순서로 적는다.
- 검증 기록에는 기준 날짜·입력·조건·결과·미검증 범위를 적는다. 코드 확인·SDK 시뮬레이션·실물 보드 검증을 구분한다.
- 상세 내용은 담당 문서 한 곳에서 관리한다. 다른 문서는 짧은 예시와 링크만 둔다.
- 명령마다 호스트·컨테이너·보드와 작업 디렉터리를 구분한다. 학습 환경의 Python 명령은 `uv run python3`를 사용한다.
- 코드 블록에는 언어를 표시한다. 명령 표의 `<값>`은 교체할 인자이며, 실행 예시에는 실제 경로나 변수를 쓴다.
- 파일·옵션·키는 코드 표기, 문서 참조는 상대 Markdown 링크를 사용한다. 이름 변경 시 코드 주석·테스트의 참조도 갱신한다.
- 본문은 한국어로 쓰고 CLI·모델·SDK 식별자는 원문을 유지한다. 용어는 정답(GT), 예측, 임계값, 릴리스, 포팅(모델 변환), 배포(보드 적용)로 통일한다.
- 아카이브는 당시 상태를 보존한다. 이전 명령·경로·수치를 현재 사용법으로 취급하지 않는다. 설계 결정의 기존 행은 수정하지 않는다.
