# Rear_Truck v03 — 중요영역(ROI) 안/밖 재집계 (2026-11-03)

iputest 1,481장의 3클래스 육안 판정(B 기준)을 **빨간 ROI**와 **파란 띠** 안/밖으로 나눠 다시 셌다. 판정·매칭은 바꾸지 않았고 카드마다 위치만 붙였다.
6,152장 평가셋은 육안 판정이 없어 GT 기준 자동 지표로 따로 집계했다(1T 3,894장만 ROI 적용, 아래 '6,152장 평가셋 ROI 집계').

> ROI 밖은 덜 중요한 영역이지 무시해도 되는 영역이 아니다. 전체에서 구한 F0 흔들림 ±17 은 ROI 내부 합격선으로 쓰지 않는다.
> 이 결과만으로 배포 합격을 정하지 않는다. 현재 결정: v02 유지, S2/S3 배포 판단 보류.

## 평가 대상 확인

- iputest 1,481장은 모두 1920×1080 이다.
- **좌우반전 여부**
  - 영상 OSD(날짜·속도 글자)는 원본에서 왼쪽 아래에 정방향으로 찍힌다. 반전 이미지라면 오른쪽 아래에 거울 글자로 나타난다.
  - 1,481장 모두 왼쪽 아래에 OSD 가 있다. 오른쪽에만 OSD 가 있는 이미지는 0장이다.
  - 수치 기준에 애매하게 걸린 162장은 대표 13장을 육안으로 확인했다. 검은 바탕이 없는 OSD 형식일 뿐 모두 정방향이었다.
  - → **반전 이미지 없음. 전부 Type A 로 평가했고 제외 이미지는 0장이다.**
- **LDC**: 평가용 이름 1,140장에는 LDC 표기가 없다. 그래서 NAS `iputest_1481` 원래 이름과 md5 로 연결해 정했다(LDC1 937 / LDC2 544).
- **합계 확인**: 안 + 밖 = 기존 전체 결과(S1 −38/+166, S2 −24/+164, S3 −14/+124, F0 +14/−20). 두 영역, 두 기준, 네 설정 모두 일치한다. 미판정은 0건이다.

## 6,152장 평가셋 ROI 집계 (자동 지표)

이 세트는 육안 판정이 없어서 GT 매칭 자동 지표만 셌다.

- **손실·획득**: S0(v02) 대비로 센다. S0 가 맞힌 GT 를 놓치면 손실, S0 가 놓친 GT 를 맞히면 획득이다. 실제 객체인지는 확인하지 않았다.
- **규칙**: `cv_6152.py` 와 같다.
  - 보드 덤프를 쓰고, 5클래스 임계값을 적용한 뒤 3클래스로 묶는다.
  - 차량끼리 IoU ≥ .45 로 겹치면 점수가 높은 것만 남긴다.
  - IoU .5 greedy 로 매칭한다.
- **박스**: GT(TP·FN·손실·획득)는 GT 박스로, FP 는 그 검출 박스로 영역을 판단했다.
- **덤프**
  - v02: `v01_symmetric_ft_bgv3/board/…output.json`
  - FT: `v01_symmetric_ft_v4ni_v5hn/6152_board/…output.json`
  - F0: `v02_symmetric_ft_bgv3/board/…output.json`
- **GT**: `ipu_gt_coco_format.json`.
- **임계값**: iputest 와 같다(각자 6,152 보드 최적, S2/S3 변경). 이 세트로 고른 값이므로 독립 검증이 아니다.
