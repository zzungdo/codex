# GT 잔존율 필터 실험 계획 (CVD_falling v2-dev)

크롭으로 잘린 GT 를 잔존율(`min_keep`)로 걸러낸 데이터셋
`~/Workspace/data/CVD/CVD_falling/releases/v2-dev` 의 효과를 측정한다.

작성 2026-09-02. 수치는 v1/v2-dev 라벨 전량 실측이며, 재현 절차는 5절에 있다.

## 1. 무엇을 묻는 실험인가

현재 학습 경로는 크롭 후 잘린 박스를 **버리지 않는다.**
`projects/src/data/dynamic_crop.py:123` 이 `instances.clip(crop_w, crop_h)` 로 박스를
크롭 경계에 자른 뒤, `remove_zero_area_boxes()` 로 **면적이 정확히 0 인 것만** 없앤다.
즉 원래 면적의 1% 만 남은 조각도 `car` 라벨을 그대로 달고 학습에 들어간다.

`min_keep` 은 여기에 "잔존 면적 비율이 임계 미만이면 박스를 버린다" 를 넣는다.
**측정할 것: 이 교체가 검출 성능을 올리는가, 그리고 임계값은 얼마인가.**

## 2. v2-dev 실측

`spec.json` 의 필터 정의:

```
crop        (424, 8) 에서 1072x1072      원본 1920x1080
min_keep    0.4                          잔존 면적 비율
size_metric sqrt_area / min_size 0.0     ← 사실상 비활성
edge_margin 0.0 / edge_mode rect         ← 사실상 비활성
lens        null
visible_classes [0,1,2,3,4]
drop_empty  false                        ← 박스 0개 이미지도 배경으로 남긴다
```

v1(1920x1080 원본 5,479장) → v2-dev(1072x1072 크롭 5,479장). 이미지 수는 그대로다.

`report.json` 과 별도로 v1 라벨에서 필터를 재구현해 대조했다 — `min_keep=0.4` 에서
**남는 박스 57,793 개로 정확히 일치**했다. 아래 분포는 그 재현 계산 결과다.

### 이 분포에서 나오는 세 가지 사실

1. **움직이는 표본이 적다.** 60.7%(41,862)는 온전해서 어떤 임계값에도 반응하지 않고,
   7,289 는 사실상 크롭 밖(<0.05)이라 항상 버려진다. 임계값 0.05~0.8 사이에서 실제로
   운명이 갈리는 박스는 **약 10,500 개, 전체의 15%** 다. 효과 크기가 작을 수밖에 없다 —
   실험 설계가 작은 차이를 잡아낼 수 있어야 한다(4절).

2. **판단의 대부분은 car, 그리고 truck 의 한 구간이다.** 부분 잔존 구간은 거의 전부 car 다.
   예외가 **truck 의 [0.30,0.40) 548 개** — 지금의 `min_keep=0.4` 가 이걸 정확히 잘라낸다.
   truck 은 필터 후 3,253 개만 남는데(원 5,061), 임계를 0.3 으로 내리면 3,801 개로
   **17% 늘어난다.** truck 처럼 표본이 적은 클래스에서 이건 큰 차이다.
   임계값 스윕에서 0.3 과 0.4 를 반드시 둘 다 돌려야 하는 이유다.

3. **motorcycle 은 죽은 클래스다.** 54 개 전부 잔존율 <0.05 라 **어떤 임계값에서도 0 개**다.
   bus 도 부분 잔존이 0 개고(444 는 크롭 밖, 248 은 온전) 임계값에 반응하지 않는다.
   즉 **이 실험이 실제로 흔드는 클래스는 car 와 truck 뿐이다.** bus·motorcycle 의 지표
   변화는 필터 효과가 아니라 잡음으로 읽어야 한다.

## 3. 착수 전에 풀어야 할 것 세 가지

### (a) train/val 분할이 없다 — 그리고 유효 표본은 43 이다

v2-dev 는 `images/` `labels/` 평면 구조로 분할이 없다. 만들어야 한다.

더 중요한 문제가 있다. 43 개 클립에서 **클립 안의 프레임이 서로 거의 같다.** 클립별
집계를 보면 정지 장면이 반복된다 — 예를 들어 `20260825_100121` 은 157 장에 car 157,
person 314, truck 157 로 **장수의 정확한 정수배**다. 같은 주차 차량·같은 사람이 매
프레임 라벨링됐다는 뜻이다.

**유효 독립 표본은 이미지 5,479 장이 아니라 클립 43 개다.** 결과적으로:

- 분할은 **반드시 클립 단위**여야 한다. 프레임 단위로 섞으면 train/val 이 사실상 같은
  장면이 되어 누수다.
- 단일 분할의 분산이 크다. 어느 클립이 val 에 가느냐가 min_keep 차이보다 지표를 더
  흔든다. → **5-fold 클립 교차검증**을 기본으로 한다(4절).
- **bus 는 클립 2 개(`151841` 131개, `151941` 117개)에만 있다.** 클립 단위로 나누면
  bus 는 train 이나 val 중 한쪽에만 몰린다. bus AP 는 어떤 분할에서도 신뢰할 수 없다 —
  실험의 판정 지표에서 제외하고 참고값으로만 남긴다.

### (b) v2-dev 는 변수를 두 개 동시에 바꿨다

기존 경로는 학습 때 `DynamicCropWrapper` 가 **매 스텝 랜덤 위치로** 크롭한다
(`dynamic_crop.py:63`, `mode='train'`). v2-dev 는 **(424,8) 고정 크롭이 이미 구워진**
이미지다. 즉 v2-dev 로 학습하면 잔존율 필터뿐 아니라 **랜덤 크롭 증강이 사라지는
효과가 같이 들어간다.** 두 변수를 분리하지 않으면 어느 쪽이 성능을 움직였는지 말할 수 없다.

→ 매트릭스에 `min_keep=0.0` 고정 크롭 조건(B)을 넣어 크롭 변경만의 효과를 먼저 뺀다.

### (c) 평가 GT 를 무엇으로 고정할 것인가

`min_keep` 을 바꾸면 **학습 라벨과 동시에 평가 GT 도 바뀐다.** 그대로 두면 조건마다 자가
채점 기준이 달라져 숫자를 비교할 수 없다. 임계값을 올릴수록 어려운 GT 가 사라져
mAP 가 저절로 올라간다.

→ **평가 GT 는 하나로 고정하고 모든 조건에 같은 것을 쓴다.** 무엇으로 고정할지는
제품 판단이 필요하다(7절). 기본값은 `min_keep=0.4` GT 를 주 지표로, `0.0`/`0.8` GT 를
민감도로 함께 보고한다.

여기에 딸린 함정: 필터로 GT 를 **삭제**하면, 모델이 절반 보이는 차를 옳게 검출해도
FP 로 집계된다. 이건 필터의 실제 위험이다. 대안은 삭제 대신 **ignore 처리**(TP 도 FP 도
아닌 영역)이고, 매트릭스의 H 조건이 이걸 본다.

참고로 저장소의 기존 평가에는 이미 다른 GT 필터가 있다 — `filter_gt_roi` 의
`roi_mode: center`(박스 중심이 ROI 안이면 유효, D-020). 이건 면적이 아니라 중심점
기준이라 `min_keep` 과 다른 정책이다. **둘을 비교하는 것도 이 실험의 일부**이므로
매트릭스에 center 조건(G)을 넣는다.

## 4. 실험 매트릭스

데이터를 제외한 모든 것(모델·하이퍼파라미터·시드·fold)을 고정하고 라벨 정책만 바꾼다.

| ID | 학습 데이터 | 목적 |
|---|---|---|
| **A** | v1 원본 + 기존 dycrop 랜덤 크롭 (필터 없음) | 현행 기준선 |
| **B** | 고정 크롭 (424,8), `min_keep=0.0` | 크롭 변경만의 효과 분리 |
| **C** | 고정 크롭, `min_keep=0.2` | 스윕 |
| **D** | 고정 크롭, `min_keep=0.3` | truck 548 개 구간 포함 |
| **E** | 고정 크롭, `min_keep=0.4` | **v2-dev 현재값** |
| **F** | 고정 크롭, `min_keep=0.6` | 스윕 |
| **G** | 고정 크롭, `roi_mode=center` | 면적 기준 대 중심점 기준 |
| **H** | 고정 크롭, `min_keep=0.4` + 미달 박스 ignore | 삭제 대 무시 |

8 조건 × 5 fold = **40 런**. 5,479 장 / imgsz 320 / batch 128 이면 epoch 당 43 iter,
50 epoch 에 2,150 iter — RTX 4090 두 장(실측 확인)에서 런당 10 분 내외로 잡으면
**전체 6~7 시간**이다. 시드를 늘리는 것보다 fold 를 쓰는 편이 (a)의 분산 문제에 직접
답하므로 시드는 fold 당 1 개로 고정한다.

H 조건은 평가 도구가 ignore 를 지원해야 성립한다. `projects/metrics/` 는 pycocotools
확장이므로 `iscrowd` 로 태울 수 있을 것으로 보이나 **미확인이다.** 확인 전까지 H 는
선택 조건으로 두고, 안 되면 A~G 7 조건 × 5 fold = 35 런으로 진행한다.

## 5. 데이터 준비

1. **빌더 스크립트를 저장소로 들인다.** v2-dev 를 만든 도구가 저장소에 없다
   (`min_keep` `sqrt_area` `clip_major` 전부 grep 0 건). `spec.json` 만으로는 재현이
   안 되므로 `tools/analyze_crop.py` 로 편입한다. 조건 B~F 를 만들려면 어차피
   같은 도구를 임계값만 바꿔 6 번 돌려야 한다.

2. **fold 분할 파일 생성** — `tools/make_clip_folds.py` (신규). 클립 43 개를 5 fold 로
   나누되 fold 별 이미지 수와 클래스 분포를 맞춘다. 분할은 **JSON 으로 고정 저장**하고
   모든 조건이 같은 파일을 읽는다. bus 클립 2 개의 배치는 기록해 둔다.

3. **재현 검증** — 각 임계값 산출물의 박스 수가 2절 표와 일치하는지 확인한다
   (0.2 → 59,948 / 0.3 → 59,463 / 0.4 → 57,793 / 0.6 → 55,627).

4. **데이터셋 yaml** — `configs/datasets/cvd_falling.yaml` 신규.
   `names` 는 5-class(bus/car/motorcycle/person/truck) 유지, 경로는 fold 별로 파생.

## 6. 학습 설정에서 반드시 확인할 것

**이중 크롭 함정.** `dataset_name: dycrop` 은 입력 이미지 크기의 **비율**로 크롭한다
(`dynamic_crop.py:62`, 기본 `crop_width_ratio=1280/1920`, `crop_height_ratio=1024/1080`).
1072x1072 로 이미 잘린 이미지에 그대로 쓰면 **714x1016 으로 한 번 더 잘린다.**
조건 B~H 는 둘 중 하나여야 한다:

- `dataset_name: default` (ultralytics 기본 `YOLODataset`) — 깔끔하지만
  `v8_transforms_dycrop` 의 증강(`aug_type`, paste 계열)을 잃는다
- `dataset_name: dycrop` + `crop_width_ratio: 1.0` `crop_height_ratio: 1.0` — 증강은
  유지되고 크롭은 항등이 된다

**조건 A 와의 증강 동등성을 위해 후자를 권한다.** 다르게 가면 증강 차이가 또 하나의
교란 변수가 된다.

**평가 시 `eval_roi_crop` 비활성화.** B~H 의 이미지는 이미 잘려 있으므로 평가에서
ROI 를 또 적용하면 이중이다. 조건 A 만 `[424, 8, 1072, 1072]` 를 쓴다.

**나머지**: `configs/experiments/CVD_falling/<조건>/fold<N>/exp.yaml`,
가중치는 `configs/releases/BSD_F606/Corner_Truck/v01/weight/pretrained_weight.pt` 에서
파인튜닝(5,479 장은 처음부터 학습하기에 너무 작다). imgsz·batch·lr 은
`configs/experiments/BSD_F606/Corner_Truck/v02/exp.yaml` 을 그대로 따르고
**전 조건 동일**하게 둔다.

## 7. 판정

**주 지표**: fold 5 개 평균 **car AP@0.50** 과 **truck AP@0.50**, 그리고 두 클래스의
mAP@0.50. person 은 필터에 거의 반응하지 않으므로(부분 잔존 480/15,848) 회귀 감시용,
bus·motorcycle 은 3절 (a)·2절 3 에 따라 **판정에서 제외**한다.

**보고 형식**: 조건별로 fold 5 개의 평균과 표준편차를 함께 낸다. fold 간 표준편차가
조건 간 차이보다 크면 "차이 없음" 이 결론이다 — 이 데이터 규모에서 충분히 가능한
결과이고, 그렇게 나오면 그렇게 기록한다.

**부가 진단**: 크롭 경계 근처(잔존율 <1.0) GT 에 한정한 recall/precision 을 따로 집계한다.
필터가 노리는 지점이 정확히 거기라, 전체 mAP 보다 이쪽이 효과를 먼저 보여줄 가능성이 높다.

**판단 기준**: E(0.4)가 B(0.0) 대비 car·truck AP 를 fold 표준편차를 넘겨 개선하면 필터
채택. D(0.3)가 E 보다 truck 에서 유의하게 좋으면 임계값을 0.3 으로 내린다. G 나 H 가
E 보다 좋으면 정책 자체를 바꾼다.

## 8. 확인 필요 / 범위 밖

- **크롭 x 오프셋 424 대 428.** v2-dev 는 424 를 썼다. 저장소의 제품 사양표는 Corner
  ROI 를 `(428, 8, 1500, 1080)` 으로 적고 있고(`README.md:299`),
  `docs/specs/eval_consolidation_plan.md` 에는 그 ROI 로 board/float 평가를 오차 0 으로
  재현하고 ROI 내부 GT 가 21,742 개로 일치했다는 실측 기록이 있다. 424 로 학습하고
  보드가 428 로 추론하면 **4px 계통 오차**가 남는다. 이 실험의 결론에는 영향이 없지만
  (전 조건 동일), 출하 전에는 맞춰야 한다.
- **motorcycle 을 어떻게 할 것인가.** 이 데이터에서 0 개다. 5-class 헤드를 유지하면
  죽은 클래스를 안고 가고, 4-class 로 줄이면 제품 사양표와 어긋난다. 이 실험은 5-class
  유지를 전제로 하되, 학습 코퍼스를 넓힐 때 다시 봐야 한다.
- **5,479 장(유효 43 장면)만으로 쓸 만한 모델이 나오지 않는다.** 이 실험은 필터 정책의
  상대 비교에만 답한다. 실제 출하 모델은 CVD_5t(57,555 장) 같은 본 코퍼스와 섞어야 하고,
  **필터 효과가 그 규모에서도 남는지는 별도로 확인해야 한다.** 여기서 이긴 임계값을
  본 학습에 그대로 옮기는 것까지가 이 계획의 범위는 아니다.
- **`labels_by_tool/` 는 쓰지 않는다.** v1 에는 자동 라벨러 출력(`labels_by_tool/`, 5,479)과
  검수본(`labels/`)이 함께 있고 표본 400 개가 전부 다르다. 이 실험은 검수본만 쓴다.

계획이었다. **v1 이 그 검수본과 같은 자산이다** — 파일명 5,479 개가 `CVD_demo_verify`
5,495 개에 전부 포함된다(차이 16 개는 v1 에서 빠짐). v1 은 1920x1080 원본을 들고 있어
크롭을 새로 뜰 수 있으므로, 오프셋이 어긋난 기존 라벨을 패치하는 그 계획은 **v2-dev
경로로 대체됐다.** 해당 문서는 폐기하거나 이 문서를 가리키도록 정리하면 된다.
