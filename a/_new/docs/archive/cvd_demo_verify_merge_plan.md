# CVD_demo 라벨 검수 반영 계획

검수본 `~/Workspace/data/CVD/CVD_demo_verify/labels` (5,495개) 를
학습셋 `~/Workspace/data/CVD/CVD_demo/{Train,Validation}/labels` 에 반영한다.

작성 2026-08-31. 아래 수치는 전량 실측이다.

## 1. 포맷 차이

| | 검수본 (CVD_demo_verify) | 학습셋 (CVD_demo) |
|---|---|---|
| 형식 | `name,x1,y1,x2,y2` (콤마) | YOLO `cls cx cy w h` (공백) |
| 좌표 | **원본 프레임 절대 픽셀** | 크롭 이미지 정규화 (0~1) |
| 클래스 | 문자열 이름 | 정수 id |
| 좌표계 | 원본 (x 224~1587, y 0~999 실측) | 크롭 1072x1072 |

**검수는 크롭 전 원본 프레임 위에서 진행됐다.** 그래서 검수본에는 크롭 영역
바깥의 객체까지 들어 있다 (아래 3절). 이게 이번 변환의 핵심 쟁점이다.

### 좌표 변환

크롭은 스케일 없는 순수 평행이동이다. 검수본과 학습셋의 미클리핑 박스
5,987쌍에서 오프셋이 **(428, 8)** 로 단일하게 나왔다 (2위 후보 38쌍, 사실상 노이즈).
박스 w/h 가 픽셀 단위까지 정확히 일치하므로 리사이즈는 없다.

```
x' = x - 428        y' = y - 8
크롭 영역 = 원본의 x∈[428,1500), y∈[8,1080)  → 1072x1072
```

### 클래스 매핑

`configs/datasets/cvd_side.yaml` / `cvd_corner.yaml` 의 5-class 정의와 일치하며,
실데이터 대조로도 확인했다 (person→3 2,113건, car→1 3,566건, truck→4 379건, bus→0 36건).
**클래스가 바뀐 박스는 0건**이다.

```
bus 0 | car 1 | motorcycle 2 | person 3 | truck 4
```

`motorcycle` 은 검수본에 54건 있으나 **전부 크롭 영역 밖**이라 학습셋에는 계속 0건이다.

## 2. 반영 범위

검수본 파일명 5,495개는 **전부** 학습셋에 존재한다 (누락 0, 이미지 누락 0).

| 구분 | 파일 수 |
|---|---|
| Train 쪽 검수 대상 | 3,749 |
| Validation 쪽 검수 대상 | 1,746 |
| **검수 대상 합계** | **5,495** |
| `*_background.txt` (검수 미대상) | 597 |
| 학습셋 전체 | 6,092 |

`_background` 597개는 이름과 달리 빈 파일이 아니라 2~23줄의 라벨을 갖고 있고,
검수본에 대응 파일이 없다. **손대지 않고 그대로 둔다.** 검수 미적용 구간이 남는다는
점은 이번 반영의 알려진 한계로 기록한다.

보이나, 실제 원인은 4단계 시각 검증에서 확인한다.

### 클리핑/드롭 처리

검수본 좌표를 크롭 영역으로 자를 때 발생하는 건수:

- 클리핑 (일부만 걸침): car 17,403 / truck 1,160 / person 494
- 드롭 (완전히 밖): car 5,788 / truck 1,263 / bus 447 / person 239 / motorcycle 54

**드롭 임계값은 클리핑 후 w 또는 h < 1px.** 기존 학습셋에는 `1 0.000000 0.279384
0.000001 0.088619` 같은 폭 0에 가까운 퇴화 박스가 **473건** 들어 있다. 이번 변환에서
이것들이 정리된다 — 삭제 1,516건 중 상당수가 여기에 해당한다.

크롭 후 박스가 0개가 되는 파일은 **0건**이다 (빈 라벨 파일은 생기지 않는다).

## 4. 실행 절차

1. **백업.** `CVD_demo/{Train,Validation}/labels` 를
   `labels.bak.20260831` 로 복사. 원본 디렉토리는 덮어쓰기 전에 반드시 남긴다.

2. **변환 스크립트 작성** — `tools/apply_cvd_demo_verify.py` (신규).
   - `--dry-run` 기본. 실제 쓰기는 `--apply` 로만.
   - 검수본 5,495개만 순회. `_background` 는 건드리지 않는다.
   - 파일별로 Train/Validation 어느 쪽인지 학습셋 기존 위치를 보고 결정한다
     (split 을 새로 계산하지 않는다 — 기존 분할 유지).
   - 출력 포맷은 기존 학습셋과 동일하게 `%d %.6f %.6f %.6f %.6f`.
   - 파일별 변경 요약(추가/삭제/수정 수)을 CSV 로 남긴다.

3. **드라이런 검증.** 스크립트가 뽑은 통계가 3절 표와 일치하는지 대조.
   불일치하면 오프셋 재추정부터 다시 본다.

4. **시각 검증.** `tools/drawing_labels.py` 로 변경된 1,026개 중 표본을 렌더링한다.
   우선 확인할 표본:
   - car 가 가장 많이 삭제된 파일 상위 20개 — 오검출 정리가 맞는지
   - 박스가 추가된 241건이 포함된 파일 — 크롭 경계에 걸친 객체인지
   - 퇴화 박스(473건)가 있던 파일 — 정상 제거인지

5. **적용.** `--apply` 실행 후 파일 수 6,092개 유지, 라벨 클래스 id 가 0/1/3/4 범위인지,
   모든 정규화 좌표가 [0,1] 인지 재확인.

6. **데이터셋 정의 정리.** `CVD_demo` 를 참조하는 yaml 이 리포에 **없다** (grep 0건).
   학습에 쓸 것이라면 `configs/datasets/cvd_demo.yaml` 을 신규 작성한다.
   names 는 위 5-class 를 그대로 쓰고, `path`/`train`/`val` 은 `cvd_corner.yaml` 의
   `Train/Validation` 대문자 규약을 따른다.

7. **기록.** `docs/changelog.md` 에 반영 사실과 3절 수치를, 크롭 오프셋 (428,8) 은
   재사용될 값이므로 `docs/technical_doc.md` 의 도메인 제약에 남긴다.

## 5. 확인 필요 사항

- **크롭 오프셋 (428,8) 의 출처.** 원본 해상도를 1920x1080 으로 보면 가운데 크롭은
  x=424 여야 하는데 실측은 428 이다. 4px 차이가 의도된 ROI 설정인지, 크롭 스크립트를
  찾아 확인하는 편이 안전하다. 다만 반영 자체는 실측 오프셋을 쓰므로 결과는 정확하다.
- **car 1,261건 감소가 검수 의도와 맞는지.** 4단계 시각 검증에서 판단한다.
- **`_background` 597개를 검수 대상으로 추가 요청할지.** 현재는 미검수 상태로 남는다.
- **8px 미만 소형 박스** car 521 / person 7 건이 반영 후에도 남는다. 학습 시
  필터링 정책이 따로 있으면 여기서 함께 정할 수 있다.
