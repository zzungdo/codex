## 소개

객체 탐지 모델의 데이터 전처리와 학습부터 ONNX export, 임베디드 변환과 평가까지 연결해 담당했습니다. 모델별 SDK 시뮬레이션·저장된 보드 결과 평가·직접 실물 보드 시험의 범위를 구분하고, 가중치·입출력 규약·평가 조건의 차이를 추적해 후보 선정과 릴리스 판단 근거를 마련했습니다.

## 핵심 업무·성과

- **학습 조건 비교:** PyTorch·Ultralytics 기반 모델의 재학습·미세조정과 조건 변경 실험을 수행하고, ONNX 출력·양자화 모델의 레이어별 오차를 대조해 학습 조건과 평가 방식의 영향을 분리했습니다.
- **출력 규약 오류 해결:** ONNX와 SDK 후처리의 채널 구성·축 순서·좌표 단위 불일치를 찾아 그래프를 수정하고, SDK 컴파일과 샘플 시뮬레이션에서 정상 박스 출력을 얻었습니다. 해당 사례의 완료 범위는 SDK 시뮬레이션까지입니다.
- **후보 교체 판단:** 저장된 보드 결과의 객체 재판정, 재학습 대조군·관심영역별 집계와 ONNX 연속 영상 분석으로 오인식 감소 뒤의 실제 객체 손실을 드러냈습니다. 기존 버전 유지·후속 후보 배포 판단 보류의 근거를 제시했습니다.
- **산출물 출처·재현성 추적:** 그래프·가중치·원시 출력을 대조해 같은 구조의 릴리스 모델과 체크포인트가 다른 가중치임을 식별했습니다. 별도 측방 탐지 모델에서는 재변환 바이너리를 직접 실물 보드에 실행하고 공통 이미지·클래스·점수 하한을 맞춰 기존 검출 결과와 비교했습니다.
- **평가·설정 통합:** 분산된 평가 경로와 좌표·클래스 매핑을 공통화하고, YAML 실험 입력과 자동 실행 기록을 분리해 과거 출력 경로의 재사용 문제를 해소했습니다. 기준 평가·짧은 학습·모델 로딩·고정 입력 및 실제 이미지 추론으로 변경 전후 동작을 대조했습니다.

## 기술 활용

Python·NumPy로 탐지 결과와 좌표·클래스 정보를 분석하고, PyTorch·Ultralytics로 모델을 학습했습니다. ONNX·ONNX Runtime과 임베디드 AI SDK로 export·변환·추론 결과를 대조했으며, Linux·Docker·YAML로 실행 환경과 설정을 관리하고 pytest·Ruff로 회귀 시험과 정적 점검을 수행했습니다.
